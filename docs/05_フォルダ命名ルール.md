# 05. フォルダ命名ルール

## 1. 基本構文

```
<NN>_<名称>
```

- `NN` = 2桁ゼロ埋めの連番
- 区切りは半角アンダースコア `_`
- 名称は日本語または英語。**全社共通ルールの禁止文字はフォルダにも適用**

```
01_設備投資
02_パイロットプラント
10_契約
99_参考資料
```

### 1.1 現行の `NN.名称` について

現在は `01.設備投資` `02.経理` のようにドット区切りが優勢です。
ドット自体に技術的な問題はありませんが、`08.法務` と `081.法務 _new` のように
**番号の桁が増えたときに階層が崩れる**（`081` が `08` の子に見える）ため、
新規は `NN_名称` とし、既存は次回の棚卸しのタイミングで移行します。

**ただし `08.広報`／`08.法務` のような番号重複だけは、移行を待たず即時解消してください。**

## 2. 連番は10刻み

サブフォルダの連番は **10刻み**（`00_` `10_` `20_` `30_` `99_`）にします。
後から `05_` `15_` を挿入でき、全体の付け替えが不要になります。

管理部の契約フォルダが既にこの形です。全社標準に昇格させます。

```
20260406_日本曹達_フェーズ2/
├── 00_契約/
├── 10_受領/
├── 20_提案/
├── 30_議事/
├── 40_請求/
└── 99_参考/
```

トップレベルのように既に1刻みで運用されている階層は、無理に振り直しません。

## 3. `99_` の用途を固定する

`99_` は **「参考資料」** の意味に固定します。

| 禁止 | 実例 | 代わりに |
|---|---|---|
| `99_未分類` | 研究開発部 Member 配下 | 3ヶ月以内に分類。残るなら `_ARCHIVE/` |
| `99.削除予定` | 事業開発部（6.4GB） | `_ARCHIVE/YYYY/` |
| `99.後で整理する` | 管理部 法務 | `_ARCHIVE/YYYY/` |
| `99.経理_old` / `99_obsolete` | 管理部 | `_ARCHIVE/YYYY/` |
| `たぶん不要` | 研究開発部 会議 | `_ARCHIVE/YYYY/` |
| `一時保管フォルダ` | 管理部 General | 分類する |
| `99_workspace` | 管理部 助成金 | 個人 OneDrive へ |

## 4. アーカイブ

各サイトのルート直下に1つだけ置きます。

```
_ARCHIVE/
├── 2024/
├── 2025/
└── 2026/
```

- 先頭の `_` により、通常フォルダより上（または下）に固まって表示されます
- **年1回、期初に棚卸し。** 3年を超えたものは削除可否を判断します
- アーカイブしたフォルダ名は変更しません（履歴の追跡性を保つため）

## 5. 日付付きフォルダ

案件・イベント単位のフォルダは日付を先頭に置きます。

```
YYYYMMDD_<主題>[_<種別>]
```

```
20260406_日本曹達_フェーズ2
20251113_ASTAR_NDA
2025_AST_013_LCMS再現性_MS686-MS705      ← 研究開発部の実験シリーズは YYYY_PJ_連番
```

- 日付は**開始日で固定**し、以後変更しません
- 期間は `YYYYMMDD-YYYYMMDD`（現行 `20250602-06_Australia` → `20250602-20250606_Australia`）
- 年月のみは月次業務フォルダに限る（`202608`）。案件フォルダでは日まで特定します

## 6. 深さと長さ

- **階層は5階層以内**（ドキュメントライブラリ直下を1階層目として数える）
- SharePoint のフルパス上限は 400 文字。フォルダ名は**30文字以内**を目安に
- 現在 6 階層に達している例:
  `03.研究開発/Member/Yukinao Maruyama/01_実験/02_テバイン/02_データ/` → 許容範囲の上限

深くなりすぎたら、階層を掘るのではなく**フォルダ名にトークンを足す**か、
上位に別フォルダを立てます。

## 7. 人名フォルダ

- 形式は `<姓>_<名>`（ローマ字、先頭大文字）: `Chino_Tomoki` `Nakagawa_Akira`
- **1人1フォルダ。** 姓のみ／名のみ／フルネームの混在を解消します
- 空フォルダ（`Freddy Chen` は0バイト）は削除します
- 退職・異動時は、成果を共有フォルダへ移してから `_ARCHIVE/` へ

## 8. 絵文字・装飾

新規フォルダに絵文字・装飾記号は使いません。

| 現行 | 変更後 |
|---|---|
| `01.ニュース📢` | `01_ニュース` |
| `01.News📢` | `01_News` |

（既存は移行フェーズで対応。緊急性は低い）

## 9. 同一ファイルの複数配置を避ける

同じファイルを複数フォルダにコピーしないでください。どれが最新かわからなくなります。

現行の例:
- `ファーメランタ_発表ひな形251021.pptx` が
  `General/精製プロジェクトMT/` と `03.研究開発/Project/精製プロジェクト/` の両方に存在
- `BY_r7h_fspoc_260417.pdf` が
  `081.法務_new/10.契約/A_NDA/BBGI.../99_参考資料/` と `04.助成金/20260511_.../募集要項/` の両方に存在
- `日本曹達株式会社御中_...請求書_20260714.pdf` が
  事業開発部 `04.Negotiation/` と管理部 `02.経理/` の両方に存在
- `④関係する研究開発テーマの事後評価報告書（写）.pdf` が助成金フォルダ内の2箇所に存在

**原本はどちらか一方に決め、もう一方には共有リンクを置きます。**
どちらが原本かは以下で判断します。

| 種類 | 原本の場所 |
|---|---|
| 締結済み契約 | 管理部 `10_契約/` |
| 契約の交渉経緯 | 事業開発部 `04.Negotiation/<案件>/` |
| 請求書・領収書 | 管理部 `02.経理/` |
| 助成金の提出書類 | 管理部 `04.助成金/<制度>/` |
| 実験データ・解析 | 研究開発部 `Project/<化合物>/` |
| 会社紹介・広報素材 | 事業開発部 `06.PR/` |
