# 07. 保存前チェックリストと FAQ

## 保存前チェックリスト（10秒）

- [ ] 先頭は **8桁の日付** `YYYYMMDD` か（`260803` や `2026035` になっていないか）
- [ ] 日付は**その文書が指す事象の日**か（保存した日になっていないか）
- [ ] 区切りは**半角アンダースコア `_`** だけか（スペース・全角 `＿` が混ざっていないか）
- [ ] **禁止文字**はないか（`　` `（）` `【】` `★◆` `@` `&` `#` `,`）
- [ ] トークンの**先頭・末尾にスペース**がないか（`_ CIC.docx` になっていないか）
- [ ] 取引先・化合物の表記は**辞書どおり**か
- [ ] 版は `_v01` `_vF` か（`最新` `修正済み` `(1)` `コピー` になっていないか）
- [ ] **社内案に版番号を付けていないか**（SharePoint 履歴で足りる）
- [ ] 拡張子は**1つ**か（`.docx.pdf` になっていないか）
- [ ] プレースホルダ（`XXX` `x月` `氏名`）が残っていないか
- [ ] 80文字以内か
- [ ] **個人 OneDrive ではなくチームサイト**に置いているか

## FAQ

### Q1. 日付は「作った日」ですか「会議の日」ですか
会議の日です。基準日 = その文書が指す事象の日。
迷ったら「あとで探すとき、頭に浮かぶ日付はどれか」で決めてください。

### Q2. 会議が続いて、資料を後日更新しました。日付は変えますか
変えません。会議日が基準です。更新は SharePoint のバージョン履歴に残ります。
別の日の会議なら別ファイルです。

### Q3. 装置から出てきたデータもリネームが必要ですか
**不要です。** `00_raw/` に原名のまま入れてください。装置ソフトが原名に依存します。
同じ階層に `00_raw_index.xlsx` を置き、原名と実験ID・サンプルIDの対応を記録します。
解析後に人が作ったファイル（Excel、PowerPoint）からルールを適用します。

### Q4. 業者からもらった請求書 PDF もリネームが必要ですか
**必要です。** 研究データとは逆です。
電子帳簿保存法が取引年月日・取引金額・取引先での検索を求めるためです。
`20260714_日本曹達_請求書_97588.pdf`

### Q5. 補助金の指定様式はどうしますか
**リネームしません。** 提出物は指定名を厳守です。
`<制度>/<YYYYMMDD>_提出/` に指定名のまま入れ、社内検討版だけルールを適用します。

### Q6. 相手先から受け取った契約ドラフトはリネームしますか
しません。`10_受領/` に原名のまま置きます。
自社が編集した版から `20260424_契約書案_日本曹達_フェーズ2_v01c.docx` のように命名します。

### Q7. 「社内案に版番号を付けない」のに、契約ドラフトには付けるのはなぜですか
社内編集は SharePoint の履歴で全部追えます。
一方、**外部に送った版は「そのとき相手が見たもの」として固定して残す必要がある**からです。
社外との往復だけが、別ファイルとして残す価値のある版です。

### Q8. `_vF`（確定版）は複数あってもいいですか
**1案件に1つだけ**です。`_vF` が2つあったら、どちらかは `_ARCHIVE/` へ。

### Q9. 台帳やマスタにも日付を付けますか
付けません。継続更新するものは日付なしで、版は SharePoint 履歴で追います。
`契約管理台帳.xlsx`、`AST_DB_菌株生産量.xlsx`、`COM_DB_進捗管理.xlsx`

### Q10. 日本語と英語が混ざってもいいですか
**混在は問題ありません。** `20260728_THB_DAT_Jar培養_MS705.xlsx` は正しい形です。
問題は同じものを2通りに書くこと（`Galantamine`/`Galanthamine`）です。

### Q11. トークンが多くなりすぎます
日付を含めて7個以上になったら、**フォルダ階層で表現すべき情報が名前に流れ込んでいます。**
どのトークンがフォルダ名と重複しているか確認してください。

### Q12. 同じ日に同じ相手と2回打ち合わせました
末尾に `_02` を付けます。`20250714_面談メモ_KHネオケム_02.docx`

### Q13. 会議の録画・Loop ノートも命名しますか
自動生成名のままで構いません（`全社会議（隔週水曜日）-20260617_155947-会議の録音.mp4`）。
ただし**恒久保管が必要なもの**をチームサイトへ移すときは、その時点でリネームします。
`20260617_MTG_全社会議_録画.mp4`

### Q14. 既存のファイルを全部リネームしないといけませんか
**いいえ。** 新規ファイルからで結構です。
一括リネームは3領域（管理部の証憑、事業開発部の面談メモ、研究開発部の指示書）だけです。
[`06_移行計画.md`](06_移行計画.md) を参照してください。

### Q15. リネームするとリンクが切れませんか
SharePoint のドキュメントID（`?d=` を含む共有リンク）は追随します。
**パスを直書きしたリンクと Excel の外部参照は切れます。**
一括リネーム前に、対象を参照している Excel を確認してください。

### Q16. 個人 OneDrive に置いてはいけませんか
作成途中の個人作業は構いません。**完成したらチームサイトへ移してください。**
個人 OneDrive は退職時に失われます。
現在、経営会議資料・提案書・チェックシートなどが個人 OneDrive と
Teams チャットに残っており、部門サイトから見つけられない状態です。

### Q17. Teams チャットにファイルを添付してもいいですか
添付は共有手段です。**原本はチームサイトに置き、チャットにはリンクを貼ってください。**
チャット添付は投稿者の OneDrive に保存され、部門で検索できません。

### Q18. 新しいプロジェクトのコードは誰が決めますか
研究開発部の PJ コードは、実験を始める前に
`03.研究開発/Management/Standardize/用語辞書.xlsx` へ登録します（研究開発部が管理）。
取引先名は事業開発部、助成金の制度略称は管理部が管理します。

### Q19. ルールに当てはまらない文書が出てきました
辞書に載っていない文書種別・取引先が出たら、**まず辞書へ追加してください。**
無理に既存コードへ押し込めると、あとで検索できなくなります。
判断に迷う場合は情報管理担当（`09.情報管理`）へ。

### Q20. このルールはいつから守ればいいですか
[`06_移行計画.md`](06_移行計画.md) のとおり、
2026年10月1日に作成する新規ファイルからです。それまでは辞書の整備期間です。
