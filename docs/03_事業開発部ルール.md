# 03. 事業開発部ルール

前提: [`01_全社共通ルール.md`](01_全社共通ルール.md) を満たしたうえで、以下を適用します。

## 0. 方針

事業開発部は**すでに全社で最も一貫した命名慣行**を持っています（面談メモ約110件）。
新しい体系は作らず、**現行慣行を正式ルールに昇格させ、逸脱15%を潰す**のが本ルールの目的です。

第1キー = 文書種別、第2キー = 相手先。探すときの入口が「誰と」だからです。

---

## 1. 基本構文

```
YYYYMMDD_<文書種別>_<相手先>[_<案件>][_v<NN>].<拡張子>
```

```
20250109_面談メモ_神戸天然物化学.docx
20260618_面談メモ_CJ Bio.docx
20250828_提案書_大塚製薬_DZN.docx
20260520_タームシート_日本曹達_フェーズ2_v01.xlsx
20251211_視察報告_河南中大恒源.docx
20260714_請求書_日本曹達_レスベラトロール.pdf
```

## 2. 文書種別（第1キー）

日本語。以下の語彙に固定します。**同義語を使わないでください。**

| 会議の議事録 | `議事録` | `議題録` `メモ` |
| 提案資料 | `提案書` | `ご提案` `提案資料` |
| 概要説明資料 | `会社紹介` / `技術概要` | `概要` |
| 見積 | `見積書` | `御見積書` `お見積り` |
| 請求 | `請求書` | `御請求書` `ご請求書` |
| 契約タームシート | `タームシート` | `TS` `term sheet` |
| 契約ドラフト | `契約書案` | `契約案` `ドラフト` `案` |
| 締結済み契約 | `契約書` | — |
| 市場・技術調査 | `調査` | `リサーチ` `Research` |

## 3. 相手先（第2キー）

### 3.1 表記は取引先名辞書に従う

正: `03.Lead Customers/00.Contact List/取引先名辞書.xlsx`

- 法人格（`株式会社` `Inc.` `Ltd.` `Co., Ltd.`）は**省略**
- 全角括弧・カンマを含む社名は辞書で半角化・省略形を定義
- 略称は辞書に1つだけ登録し、それ以外は使わない

| 現行の揺れ | 辞書表記 |
|---|---|
| `群栄化学` / `群栄化学工業` / `群栄化学工業株式会社` | `群栄化学工業` |
| `ヤエガキ発酵技研` / `ヤヱガキ発酵技研` | `ヤヱガキ発酵技研` |
| `三菱商事ライフサイエンス株式会社` / `三菱商事ライフサイエンス` | `三菱商事ライフサイエンス` |
| `アサヒクオリティイノベーションズ` / `アサヒクオリティーアンドイノベーションズ` / `アサヒQAI` | `アサヒクオリティアンドイノベーションズ` |
| `EuroAPI` / `Euro API` | `EuroAPI` |
| `Scale Up Bio` / `ScaleUp Bio` | `ScaleUp Bio` |

| `神戸天然物化学` / `神戸天然物化学（CDMO）` | `神戸天然物化学`（区分は案件トークンへ） |

### 3.2 相手先が複数のとき

`-` で連結し、最大2社まで。3社以上は主催者または代表1社＋`他`。

```
20250116_面談メモ_東ソーAIA-金森産業.docx
20250604_面談メモ_ソーシングブラザーズ-KHネオケム.docx
```

### 3.3 個人名は入れない

```
✗ 20250424_面談メモ_アピ株式会社 三木様.docx
○ 20250424_面談メモ_アピ.docx
```

同日・同相手で複数回面談した場合のみ `_02` を末尾に付けます
（`20250714_面談メモ_KHネオケム_02.docx` は既に正しい形です）。

## 5. 契約ドラフトの版管理

事業開発部で最も乱れている領域です。全社ルール §4 をそのまま適用します。

### 現行

```
日曹-ファーメランタ_フェース゛2契約書案_0420版_FLTコメント0424.xlsx
日曹-ファーメランタ_フェース２契約書案_0611.docx
日曹-ファーメランタ_フェース２契約書案_0611_0612FLT.docx
日曹-ファーメランタ_フェース２契約書案_0611_0612FLT_vSent.docx
日曹-ファーメランタ_フェース２契約書案_0617.docx
日曹-ファーメランタ_フェース２契約書案_0617_0617FLT_2.docx
日曹-ファーメランタ_フェース２契約書_vF.docx.pdf
```

問題: 日付が中置で2つ、`フェース`（正: フェーズ）、全角`２`、`フェース゛`（濁点分解）、
`FLT`（自社略称）が版の意味で使われている、`vSent` と `_2` が併存、二重拡張子。

### 変更後

```
20260420_契約書案_日本曹達_フェーズ2_v01.docx        ← 自社から送付
20260424_契約書案_日本曹達_フェーズ2_v01c.docx       ← 相手先コメント返し
20260611_契約書案_日本曹達_フェーズ2_v02.docx
20260612_契約書案_日本曹達_フェーズ2_v02c.docx
20260617_契約書案_日本曹達_フェーズ2_v03.docx
20260617_契約書_日本曹達_フェーズ2_vF.pdf             ← 締結版（種別が「契約書」に変わる）
```

**締結版が確定したら、管理部の `081.法務_new/10.契約/` に契約管理番号付きで登録します。**
事業開発部フォルダに残るのは交渉経緯、管理部にあるのが原本です（管理部ルール §2）。

## 6. フォルダ命名

### 6.1 `04.Negotiation` / `03.Lead Customers` の案件フォルダ

```
YYYYMMDD_<相手先>_<契約種別/案件>
```

日付は**初回接触日または最初の契約締結日**で固定し、以後変えません。

```
○ 20260406_日本曹達_フェーズ2
○ 20250520_住友林業_NDA
✗ 20251113 ASTAR SIFBI NDA        → 20251113_ASTAR_NDA
✗ 20251222 GEA NDA                → 20251222_GEA_NDA
✗ 20251211 Scale Up Bio           → 20251211_ScaleUp Bio_NDA
✗ 202608 BBGI MOU                 → 20260801_BBGI_MOU（日を特定して8桁に）
✗ 20260702_東京化成                → 20260702_東京化成_NDA（契約種別を必ず付ける）
✗ Bedoukian                       → 20240XXX_Bedoukian_NDA（日付を調べて付与）
✗ アサヒユウアス                   → <締結日>_アサヒユウアス_<種別>
```

同一相手先で日付付き・日付なしのフォルダが併存している場合（`20260623_三菱商事ライフサイエンス` と
`三菱商事ライフサイエンス`）は、**統合してください。**

### 6.2 案件フォルダ内の標準構造

管理部の契約フォルダ構造（`00_NDA / 10_MOU / 20_Support Letter / 99_参考資料`）を採用します。

```
20260406_日本曹達_フェーズ2/
├── 00_契約/          ← 契約書案・締結版
├── 10_受領/          ← 相手先から受領した原本（リネーム禁止）
├── 20_提案/          ← 提案書・タームシート
├── 30_議事/          ← 議事録・面談メモ
├── 40_請求/          ← 請求書・入金確認
└── 99_参考/
```

連番は**10刻み**。後から `05_` `15_` を挿入できます。

## 7. アーカイブ

`99.削除予定`（6.4GB）と `08.知財（削除予定）`（636MB）が長期滞留しています。

- 「削除予定」フォルダは作らない。判断できないものは `_ARCHIVE/YYYY/` へ移す
- `_ARCHIVE/` は年1回（期初）に棚卸し。3年を超えたものは削除を判断
- 知財は管理部 `081.法務_new/30.知財` が正。事業開発部側は削除またはリンクに置換

## 9. 事業開発部だけの追加禁止事項

| 禁止 | 理由 |
|---|---|
| `FLT` を版の意味で使う | 自社略称であり版ではない。`_v01c` を使う |
| 相手先名に個人名・敬称を付ける | `アピ株式会社 三木様` → `アピ` |
| 契約フォルダを契約種別なしで作る | 後から `20260702_東京化成` の中身が判別できない |
| 「削除予定」フォルダの新規作成 | `_ARCHIVE/YYYY/` を使う |
| 二重拡張子 | `.docx.pdf` は PDF 化時に必ず `.pdf` のみへ |
