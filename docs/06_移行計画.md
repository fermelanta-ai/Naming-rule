# 06. 移行計画

## 0. 原則

**既存ファイルは原則リネームしません。** 数十万件を一括で変えると、
リンク切れ・Excel の外部参照切れ・過去のメールからの到達不能が発生します。

新規ファイルから適用し、一括リネームは**費用対効果の高い3領域に限定**します。

SharePoint はファイルをリネームしてもドキュメントID（`Doc ID`）が保持されるため、
`?d=` 形式の共有リンクは追随します。ただし**パスを直書きしたリンク・数式は切れます。**
一括リネーム前に、対象フォルダを参照している Excel の外部参照を確認してください。

| # | 成果物 | 担当 | 場所 |
|---|---|---|---|
| 0-1 | 取引先名辞書 | 事業開発部 | `03.Lead Customers/00.Contact List/取引先名辞書.xlsx` |

これは説明が1分で済み、効果が最も大きい項目です。

## Phase 1 — 新規ファイルに適用（2026-10-01〜）

- 新しく作るファイル・フォルダのみルール適用。既存は触らない
- 各部門で「よく使う3パターン」だけ覚えてもらう

| 部門 | 覚えるのはこの3つ |
|---|---|
| 研究開発部 | `YYYYMMDD_<PJ>_DAT_<内容>_<菌株>.xlsx` / `..._RPT_...` / `..._MTG_...` |
| 事業開発部 | `YYYYMMDD_面談メモ_<相手先>.docx` / `..._提案書_...` / `..._契約書案_..._v01.docx` |
| 管理部 | `YYYYMMDD_<取引先>_請求書_<金額>.pdf` / `YYYYMMDD_<契約名>_<相手先>_<管理番号>.pdf` |

- Word / Excel / PowerPoint のテンプレート（`.dotx` `.xltx` `.potx`）を各部門で用意し、
  「名前を付けて保存」時の既定名をルール準拠にします
  （事業開発部の `面談メモ_テンプレート.dotx` が既にあります）

## Phase 2 — 限定的な一括リネーム（2026-11〜2027-01）

投資対効果の高い3領域のみ。PnP PowerShell または Power Automate で機械的に実行します。

### 2-1. 管理部: 経理直下の証憑（最優先・法令対応）

- 対象: `02.経理` 直下の約30ファイル＋`01.支払・購買管理` 配下
- 手作業が必要（金額・取引先は中身を見ないとわからない）
- **税務調査リスクの解消が目的。** 完了期限を切ってください
- 併せて、`02.経理` 直下へのファイル直置きを禁止し、`<年度>/<月>/` へ移動

### 2-2. 事業開発部: 面談メモの逸脱

- 対象: `03.Lead Customers/01.面談メモ` の約20ファイル
- 大半は機械的に処理可能:
  - 第3トークン先頭の半角スペース削除（約15件）
  - 全角 `＿` → 半角 `_`（1件）
  - 半角スペース区切り → `_`（5件）
- 種別トークン欠落・日付破損（`2026035_`）の6件のみ手作業

### 2-3. 研究開発部: 日付形式の統一

- 対象: `Management/指示書/` の `YYMMDD_指示書_<名前>さん.docx` 約45件
  → `YYYYMMDD_COM_INS_日次指示_<姓>.docx`
- 完全に規則的なので、正規表現で一括変換可能
- 併せて `Member/chino` と `Member/Tomoki Chino` の統合、`Freddy Chen`（空）の削除

### 実行時のチェック

1. 対象フォルダのバックアップ（バージョン履歴が有効なことを確認）
2. リネーム対象の一覧を CSV で出力し、担当部門がレビュー
3. 参照している Excel の外部参照・Power BI データセットを確認
4. 実行後、リンク切れの報告窓口を1週間開ける

## Phase 4 — 定着（継続）

### 四半期チェック

情報管理担当が四半期ごとに以下をスキャンし、部門長へ報告します。

| チェック項目 | 判定 |
|---|---|
| ファイル名に禁止文字を含む | 全角スペース `　`、`＿`、`（）`、`【】`、`★◆`、`@`、`&`、`#` |
| 日付が8桁でない | 先頭6桁 or 日付なし |
| 版表記が禁止語 | `最新` `修正済み` `コピー` `(1)` `new` `old` |
| プレースホルダ未置換 | `XXX` `x月` `氏名` `<` `>` |
| 二重拡張子 | `.docx.pdf` `.xlsx.xlsx` |
| 名前が80文字超 | — |
| 一時置き場フォルダの存在 | `削除予定` `後で整理` `未分類` `obsolete` `たぶん` |

（PnP PowerShell で `Get-PnPListItem` から `FileLeafRef` を取得して正規表現で判定できます）

### 新規メンバーのオンボーディング

- 入社時オリエンテーションに「保存場所と命名」を10分入れる
- 部門テンプレートの場所を案内する
- 最初の1ヶ月は、部門内のレビュー時にファイル名も見る

## 想定される抵抗と対応

| 声 | 対応 |
|---|---|
| 「研究が忙しくてファイル名まで手が回らない」 | 覚えるのは3パターンだけ。テンプレートの既定名で自動化する。生データはリネーム不要と明示 |
| 「今のやり方で自分は探せている」 | 探せなくなるのは本人ではなく、後任と他部門。退職時に `Member/` が12.9GBのブラックボックスになる |
| 「一括リネームでリンクが切れる」 | 一括リネームは3領域のみ。SharePoint の Doc ID リンクは追随する。事前に一覧レビューする |
| 「英語コードは覚えられない」 | 研究開発部のみコード制。既に `MS686` を日常的に使っており、同種の負荷 |
| 「管理部の証憑は業者名のままでいい」 | 電子帳簿保存法の検索要件。整理の話ではなく法令対応 |
