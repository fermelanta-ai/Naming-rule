## 2. v1 へのフィードバック

> 前提: 本リポジトリには v1 の Markdown がコミットされておらず（コミット履歴ゼロ）、
> SharePoint 上にも v1 に該当する Markdown を発見できませんでした。
> 以下は「実態調査で見えたが、表層的な棚卸しでは拾えない論点」として整理しています。
> v1 の原文を共有いただければ、差分形式で追記します。

### 2.1 v1 が押さえていたはず、かつ正しい点（v2 でも維持）

- 日付を先頭に置く。3部門とも既に日付先頭が優勢で、これは変える必要がありません。
- `_`（アンダースコア）区切り。既存の良い慣行と一致します。
- フォルダに `NN.` の連番を振る。全社に定着しています。

### 2.2 v1 が届いていない論点（v2 の追加点）

| # | 論点 | なぜ表層的な調査では見えないか |
|---|---|---|
| 1 | **研究開発部は「命名の乱れ」ではなく「命名軸そのものが未定義」** | トップ2階層だけ見ると `Project/Cannabinoid` `Member/...` と整然として見えます。実際の乱れは4〜6階層目（`Member/Yukinao Maruyama/01_実験/02_テバイン/02_データ/培養結果@260728.xlsx`）に集中しています。 |

## 3. v2 の設計方針

1. **全社で統一するのは、検索とツールを壊す要素だけに絞る。**
   文字種・日付形式・版表記・禁止語。ここは例外を認めません。
2. **意味の並び順（第1キー／第2キー）は部門が決める。**
   研究開発部の主検索キーは「化合物・プロジェクト」、事業開発部と管理部は「文書種別・相手先」で、
   業務が違う以上、無理に一本化すると必ず形骸化します。
3. **既存の最良慣行を標準に昇格させる。** 新しい体系を発明しません。
   - 管理部法務の `日付_文書名_相手先_管理番号`
   - 事業開発部の `日付_文書種別_相手先`
   - 研究開発部の `日付_種別_対象`（指示書）と `NN_用途` サブフォルダ
   - 契約フォルダの `00_ / 10_ / 20_ / 99_` 10刻み連番
4. **既存ファイルは原則リネームしない。** 新規ファイルから適用し、
   一括リネームは費用対効果の高い3領域のみに限定します（`06_移行計画.md`）。
5. **ルールの前に辞書を作る。** 取引先名・化合物/菌株・制度略称の3辞書がないと、
   ルールを守っても検索は当たりません。
