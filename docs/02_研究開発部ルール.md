# 02. 研究開発部ルール

前提: [`01_全社共通ルール.md`](01_全社共通ルール.md) を満たしたうえで、以下を適用します。

## 0. なぜ研究開発部だけ「主題が先」なのか

事業開発部・管理部は「文書種別 → 相手先」の順ですが、研究開発部は逆です。

研究開発部でファイルを探すときの入口は、ほぼ常に**化合物・プロジェクト**です。
「アスタキサンチンのLC-MSデータ」は探しますが、「LC-MSデータのアスタキサンチン」とは探しません。
また、`Project/Astaxanthin/Data/` のようにフォルダが既に文書種別で切られている場所が多く、
そこで種別を先頭に置くと全ファイルが同じ文字列で始まり、整列の意味がなくなります。

したがって研究開発部は **第1キー = PJコード、第2キー = 文書種別** とします。

## 4. 菌株ID・条件トークン

菌株IDは**必ず `MS` + 数字**（`MS686` `MS705` `MS1031`）。
複数株は `-` で連結: `MS686-MS705`。4株以上なら代表株のみ書き、全リストは中身に記載します。

条件は短縮形で、カンマではなく `-` 連結:

```
✗ 2025-Astaxanthin14 (Jar, KWB, pH7.6, MS705, MS910, 抽出条件 Acetone vs EtOH)
○ 20251120_AST_EXP_Jar-KWB-pH7.6_MS705-MS910_AcetoneVsEtOH
```

よく使う条件トークン: `Jar` `Flask` `Plate` `KWB` `pH7.6` `IPTG` `heat` `noheat` `RawData`

## 5. 実験シリーズフォルダ

現行の `2025-Astaxanthin13 (MS686 LC-MS再現性, MS705由来Astaxanthinの産生画分解析）` を、
以下に置き換えます。

```
<YYYY>_<PJコード>_<連番3桁>_<要約>
```

```
2025_AST_001_標準品検討
2025_AST_013_LCMS再現性_MS686-MS705
2025_AST_014_Jar抽出溶媒比較_MS705-MS910
2025_AST_015_Jar生産量比較_MS705他6株
2025_AST_016_Jar生産量比較_MS706-MS764-MS825
```

- 連番は**3桁ゼロ埋め**（`001`）。現行の `Astaxanthin1` と `Astaxanthin13` は整列が壊れます。
- 要約は**30文字以内**。括弧・カンマ禁止。
- 詳細条件はフォルダ名ではなく、フォルダ直下の `README.md` または `00_実験概要.xlsx` に書きます。
  **フォルダ名は索引、中身は記録**という役割分担にします。

### シリーズフォルダの内部構造（標準）

```
2025_AST_013_LCMS再現性_MS686-MS705/
```

## 7. 個人フォルダ（`Member/`）の扱い

### 7.1 命名

```
Member/<姓>_<名>/
```

ローマ字、姓が先、先頭大文字。**1人1フォルダ。** 現行の重複・ゆれを解消します。

| 現行 | 変更後 |
|---|---|
| `Member/chino` と `Member/Tomoki Chino`（同一人物で2フォルダ） | `Member/Chino_Tomoki`（統合） |
| `Member/Akira Nakagawa` | `Member/Nakagawa_Akira` |
| `Member/Yukinao Maruyama` | `Member/Maruyama_Yukinao` |
| `Report/Hara`、`Instructions/Yuki Hara` | `Hara_Yuki` |
| `Report/Sekiyama`、`Member/Naotaka Sekiyama` | `Sekiyama_Naotaka` |
| `Report/Motoyoshi`、`Member/So Motoyoshi` | `Motoyoshi_So` |
| `Report/Kumar`（名のみ） | 姓名を確認して `<姓>_<名>` |
| `Member/Freddy Chen`（0バイトの空） | 削除 |

### 7.2 位置づけ（重要）

**`Member/` は個人の作業場であり、成果の保管場所ではありません。**

- 共有すべき成果（データ・解析・報告）は `Project/<化合物>/` 配下に置きます。
- `Member/` に置いてよいのは、検討中のメモ・私的な参考資料・下書きのみ。
- 退職・異動時に `Member/<本人>/` は**アーカイブに移す前に棚卸し**し、
  成果は `Project/` へ移設します。

現在 `Member/` 配下に 19GB あり、`Member/chino/download files` だけで 12.9GB です。
`Project/` 全体（17.4GB）に匹敵する量が個人フォルダに滞留しています。

### 7.3 個人フォルダ内の標準構造

丸山さんの構造が良いので、これを全員の標準にします。

```
Member/<姓>_<名>/
├── 01_実験/
│   ├── 01_<PJコード>_<テーマ>/
│   │   ├── 01_方針/
│   │   ├── 02_データ/
│   │   ├── 03_作業手順/
│   │   └── 04_文献調査/
├── 02_資料/
├── 10_事務/
└── 99_未整理/     ← 3ヶ月以内に空にする
```

※ 現行の `01_方針@予定等` は `@` が禁止文字のため `01_方針` に改めます。

## 8. 用語辞書の運用（研究開発部の最優先タスク）

`03.研究開発/Management/Standardize/用語辞書.xlsx` に以下を1シートずつ持ちます。

| シート | 列 |
|---|---|
| PJコード | コード / 正式名称(英) / 別名(和) / 開始日 / 状態 |
| 化合物 | 正式表記 / 誤記例 / CAS番号 / 関連PJコード |
| 菌株 | 菌株ID / 宿主 / 導入遺伝子 / 作製日 / 作製者 / 親株 |
| 装置・分析法 | 略称 / 正式名称 / 設置場所 |
| 文書種別 | コード / 意味 / 例 |

**このファイルが命名ルール本体より重要です。**
`Galanthamine`/`Galantamine`、`Reticuline`/`Retculine` のような表記ゆれは、
菌株DBと実験データの突合を静かに壊し、再現性の議論そのものを損ないます。

## 10. 研究開発部だけの追加禁止事項

| 禁止 | 理由 |
|---|---|
| ファイル名に `@` を使う | `培養結果@260728.xlsx` 形式。日付は先頭 `_` 区切りへ |
| 機器出力ファイルのリネーム | 装置ソフトが原名に依存。`00_raw/` に原名格納 |
| 化合物名の独自略記 | 辞書にない略記は禁止。`Retculine` のような誤記が伝播する |
| `たぶん不要` `99_未分類` の常設 | 3ヶ月で棚卸し。残すなら `_ARCHIVE/YYYY/` へ |
| 個人フォルダへの成果の抱え込み | 共有すべきものは `Project/` 配下へ |
