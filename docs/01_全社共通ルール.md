# 01. 全社共通ルール（コンセンサスルール）

**適用範囲**: SharePoint チームサイト、OneDrive for Business、Teams 上の全ファイル・全フォルダ。
**対象外**: §6 に列挙した例外のみ。

このドキュメントの §1〜§5 は**部門を問わず全員が守る**必須ルールです。
意味の並び順（第1キー・第2キー）は各部門ルールで定義します。

---

## 1. 基本構文

```
YYYYMMDD_<第1キー>_<第2キー>[_<補足>][_v<NN>].<拡張子>
```

| 要素 | 必須 | 内容 | 部門別定義 |
|---|---|---|---|
| `YYYYMMDD` | ● | 文書の**基準日**（§3） | 共通 |
| 第1キー | ● | 研究開発部: プロジェクト/化合物コード<br>事業開発部: 文書種別<br>管理部: 文書種別 | 各部門ルール |
| 第2キー | ● | 研究開発部: 文書種別<br>事業開発部: 相手先<br>管理部: 相手先 or 制度略称 | 各部門ルール |
| 補足 | ○ | 菌株ID・条件・案件名・担当者など。最大2トークン | 各部門ルール |
| 版 | ○ | `_v01` `_v02` … `_vF`（§4） | 共通 |

**トークン数は日付を含めて 3〜6 個。** 7 個以上になったら、フォルダ階層で表現すべき情報が
ファイル名に流れ込んでいます。

### 良い例（既存の優良慣行）

```
20260212_CONFIDENTIAL DISCLOSURE AGREEMENT_BBGI Public Company Limited_A20260019.pdf
20250109_面談メモ_神戸天然物化学.docx
20260803_INS_日次指示_河端.docx
20260728_THB_DAT_Jar培養_MS705.xlsx
```

## 2. 文字ルール

### 2.1 区切り文字

| 用途 | 記号 | 例 |
|---|---|---|
| トークン区切り | 半角アンダースコア `_` | `20260728_面談メモ_東レ` |
| 語内の連結 | 半角ハイフン `-` | `LC-MS`、`MS686-MS705`、`heat-noheat` |
| 階層の代用 | **使わない**（フォルダで表現） | — |

### 2.2 使用可能な文字

- 半角英数字 `A-Z a-z 0-9`
- 半角 `_` と `-`
- 日本語（ひらがな・カタカナ・漢字）— **文字のみ。全角記号は不可**
- ドットは拡張子の直前に1個だけ

### 2.3 禁止文字（例外なし）

| 記号 | 理由 |
|---|---|
| 半角スペース ` ` | URL で `%20` になり、リンク・スクリプト・自動処理が壊れる |
| 全角スペース `　` | 目視で気づけず、検索が一致しない |
| 全角アンダースコア `＿` | 半角 `_` と別文字。並び順・検索が壊れる |
| `（） 【】 「」 〔〕 ＜＞` | 全角括弧。半角括弧と混在すると整列不能 |
| `( )` 半角括弧 | 補足情報は `_` トークンで表現する（例外: 拡張子内の慣用なし） |
| `& # % * ? : " < > \| / \` | OS / SharePoint / URL のいずれかで予約または不具合 |
| `@` | `培養結果@260728.xlsx` のような日付区切り用途を禁止。メール以外で使わない |
| `★ ◆ ● ▲ ※ 〜 ～` | 装飾記号。ソートが破綻する |
| `、 。 ，` | 全角句読点 |
| 絵文字 | フォルダ名の `📢` も新規では不可（既存は §5 移行対象） |
| 先頭・末尾の空白 / ドット | SharePoint が保存を拒否する場合がある |

### 2.4 長さ

- **ファイル名は 50 文字以内を目安、80 文字を上限。**
- SharePoint のフルパス上限は 400 文字。フォルダ階層は 5 階層以内（`05_フォルダ命名ルール.md`）。
- 上限に当たったら、削るのは補足トークン。日付・第1キー・第2キーは削らない。

### 2.5 大文字・小文字

- コード類（PJコード、文書種別コード、契約区分）は**すべて大文字**: `THB` `DAT` `A20260019`
- 英語の固有名詞は正式表記どおり: `BBGI Public Company Limited`（社名内の半角スペースのみ許容）
- SharePoint は大文字小文字を区別しないため、`Report` と `report` を別物として使わない

## 3. 日付ルール

### 3.1 形式

| 種類 | 形式 | 例 |
|---|---|---|
| 単日 | `YYYYMMDD`（8桁固定） | `20260728` |
| 期間 | `YYYYMMDD-YYYYMMDD` | `20250602-20250606` |
| 月次 | `YYYYMM`（6桁）※月次文書のみ | `202608` |
| 年次 | `YYYY` または `FY2026` | `FY2026_勘定科目.xlsx` |

**`YYMMDD`（6桁の日）は禁止。** `260803` と `202608`（年月）が区別できず、
`202511313` のような桁落ちタイポも検知できません。

### 3.2 基準日の定義

日付は**その文書が指す事象の日**です。ファイルを保存した日ではありません。

| 文書 | 基準日 |
|---|---|
| 面談メモ・議事録 | 会議・面談の実施日 |
| 契約書（締結版） | 締結日 |
| 契約書（ドラフト） | 相手先へ送付した日 / 受領した日 |
| 実験データ | 測定日（培養なら本培養開始日） |
| 報告書 | 報告対象期間の末日、または報告会の日 |
| 請求書・領収書 | 発行日（取引年月日） |
| 提案書 | 提出日 |

判断に迷ったら「後日この文書を探すとき、頭に浮かぶ日付はどれか」で決めます。

### 3.3 位置

日付は**必ず先頭**。中置（`分析技術と技術レベル_260708_平野.pptx`）・
後置（`取引先信用調査一覧_20260717.xlsx`）は禁止です。

例外: 継続更新される台帳・マスタは日付を付けません（§4.3）。

## 4. 版（バージョン）ルール

### 4.1 原則: 社内案に版番号を付けない

SharePoint にはバージョン履歴があります。社内での編集は履歴で追えるため、
`_v1` `_v2` を作らないでください。ファイルを増やすとリンクが分散します。

### 4.2 版番号を付けてよい唯一の場面: 社外との往復

相手先に送った／相手先から受け取った版だけが、別ファイルとして残す価値があります。

| 表記 | 意味 |
|---|---|
| `_v01` `_v02` … | 自社から相手先へ送付した版（連番） |
| `_v02c` | `v02` に対する**相手先コメント返し**（c = counterparty） |
| `_vF` | 締結版・確定版。**1案件に1つだけ** |

```
20260406_契約書案_日本曹達_フェーズ2_v01.docx
20260424_契約書案_日本曹達_フェーズ2_v01c.docx
20260611_契約書案_日本曹達_フェーズ2_v02.docx
20260617_契約書案_日本曹達_フェーズ2_vF.pdf
```

### 4.3 禁止する版表記

| 禁止 | 実例 | 代わりに |
|---|---|---|
| `最新` `修正済み` `確定` `final` | `(修正済み).pptx` | SharePoint 履歴、または `_vF` |
| `(1)` `(2)` `コピー` `- コピー` | `研究チーム_日次タスク管理 (1).xlsx` | 元ファイルを直接編集 |
| `new` `old` `New_` `OLD_` | `New_20251222_...` / `OLD_20250812_...` | 旧版は `_ARCHIVE/` へ移動 |
| 日付の重ね書き | `..._0611_0612FLT_vSent.docx` | 先頭日付を更新し `_v0N` |
| `_案` `（案）` | `20260XXX_ステージゲート運用規定（案）.docx` | `_v01`（未確定は版番号で表す） |
| 二重拡張子 | `..._vF.docx.pdf` | `.pdf` のみ |
| プレースホルダ未置換 | `20260XXX_` `業務委託者氏名_請求書_x月分` | 保存前に必ず置換 |

## 5. 言語・表記ゆれルール

### 5.1 言語の選び方

| 領域 | 言語 |
|---|---|
| 研究開発部の化合物・菌株・技術用語 | **英語**（`Astaxanthin` `MS686` `LC-MS`） |
| 文書種別 | 部門ルールで固定（研究開発部は英語3文字コード、他は日本語） |
| 国内取引先・国内制度名 | 日本語 |
| 海外取引先 | 現地正式表記（英語） |

**同一ファイル名内で日英が混在するのは問題ありません。** 混ぜないのは表記ゆれです。

### 5.2 表記ゆれは辞書で潰す

以下の3辞書を正とし、ファイル名では辞書表記のみを使います（`98_用語辞書.md`）。

| 辞書 | 管理者 | 保管場所 |
|---|---|---|
| 取引先名辞書 | 事業開発部 | `03.Lead Customers/00.Contact List/取引先名辞書.xlsx` |
| 化合物・菌株・PJコード辞書 | 研究開発部 | `03.研究開発/Management/Standardize/用語辞書.xlsx` |
| 助成金・制度略称辞書 | 管理部 | `04.助成金/00_制度略称辞書.xlsx` |

現時点で確認済みの要修正ゆれ:

| 揺れ | 正 |
|---|---|
| `Galantamine` / `Galanthamine` | `Galanthamine` |
| `Retculine` / `Reticuline` | `Reticuline` |
| `群栄化学` / `群栄化学工業` / `群栄化学工業株式会社` | `群栄化学工業` |
| `ヤエガキ発酵技研` / `ヤヱガキ発酵技研` | `ヤヱガキ発酵技研` |
| `フェース` / `フェーズ` / `フェース゛` | `フェーズ` |
| `Fomat` / `Format` | `Format` |
| `templete` / `template` | `template` |
| `チエックシート` / `チェックシート` | `チェックシート` |

### 5.3 法人格の扱い

`株式会社` `Inc.` `Ltd.` `Co., Ltd.` は**ファイル名では省略**します（辞書に正式名称を持つ）。
`,` を含む法人格はカンマ禁止ルールにも抵触します。

```
✗ 20250418_面談メモ_三菱商事ライフサイエンス株式会社.docx
○ 20250418_面談メモ_三菱商事ライフサイエンス.docx
✗ Cataya Bio (Shanghai) Co., Ltd
○ Cataya Bio Shanghai
```

例外: **契約書の締結版**は法的正確性のため正式名称を使います（管理部ルール §2）。

## 6. 例外（リネームしてはいけないファイル）

以下は**原名のまま保存**します。リネームすると業務が壊れます。

| 種類 | 例 | 扱い |
|---|---|---|
| 分析機器の生データ | LC-MS / NMR / qPCR の出力ファイル・フォルダ | `00_raw/` に原名格納。同階層に索引（`00_raw_index.xlsx`）を置き、ファイル名と実験IDの対応を記録 |
| 相手先から受領した契約ドラフト | 相手先が命名した `.docx` | `10_受領/` に原名格納。自社編集版から命名ルール適用 |
| 補助金・行政の指定様式 | `Ⅱ-D1_提案書__バイオセン_ファーメランタ株式会社.pdf`、`BY_r7h_fspoc_260417.pdf` | 提出物は指定名を厳守。控えは `90_提出控/` に原名格納 |
| Teams 会議録画・Loop ノート | `全社会議（隔週水曜日）-20260617_155947-会議の録音.mp4` | 自動生成名のまま。ただし**恒久保管する分だけ**チームサイトへ移動する際にリネーム |
| ソースコード・設定ファイル | `package.json` 等 | 各エコシステムの規約に従う |

**業者発行の請求書・領収書は例外ではありません。** 受領時にリネームが必須です（管理部ルール §1）。

## 7. 保存場所ルール（命名ルールの前提）

命名を整えても、置き場所がバラバラだと検索できません。最低限の原則を定めます。

| 種類 | 保存先 |
|---|---|
| 部門の業務成果物（報告書・議事録・契約・データ） | **必ず部門チームサイト**。個人 OneDrive 不可 |
| 作成途中の個人作業ファイル | 個人 OneDrive 可。ただし**完成した時点でチームサイトへ移動** |
| Teams チャットに添付したファイル | 添付は共有手段。原本は必ずチームサイトに置き、チャットには**リンクを貼る** |
| 会議の録画・自動議事録 | 既定の保存先のまま。恒久保管が必要なものだけチームサイトへ移動 |

**チームサイトが原本（SSOT）です。** 個人 OneDrive のファイルは退職時に失われます。

同一ファイルを複数フォルダにコピーしないでください。
（例: `ファーメランタ_発表ひな形251021.pptx` が `General/精製プロジェクトMT/` と
`03.研究開発/Project/精製プロジェクト/` の両方に存在）
必要なら SharePoint の「ショートカット」または共有リンクを使います。

## 8. 個人情報の扱い

- **ファイル名にフルネームを入れない。** 検索インデックスや共有リンクの経路で、
  権限外に氏名が見えるリスクがあります。
- 履歴書・評価・給与・健康情報など機微情報は、ファイル名を
  `YYYYMMDD_<書類種別>_<社員番号>.<ext>` とし、氏名は含めません。
- ID・パスワードをファイル名に含めない（`..._口座振替案内とIDPW_....pdf` は要改名）。
- 研究開発部の日次指示書のように、**業務上わかりやすさが優先される場面では姓のみ**を使います
  （`20260803_INS_日次指示_河端.docx`）。敬称（`さん` `様`）は付けません。
